# 実機検証（2026-10-23 JST）

## 環境

* Ubuntu 26.04.1 LTS / kernel 7.0.0-38-generic
* GPU: AMD Radeon AI PRO R9700、PCI ID 1002:7551
* PCI BDF: 0000:0b:00.0、DRM card1、hwmon1
* amdgpu: 7.1.3.31500000
* AMD SMI tool/library: 27.0.0、ROCm: 10.0.0
* 再起動前のppfeaturemask: 0xfff7bfff
* 再起動後のppfeaturemask: 0xfff7ffff

## 変更前

`amd-smi metric --fan --temperature --json`:

```json
{"fan": {"speed": 51, "max": 255, "rpm": 1065,
         "usage": {"value": 20.0, "unit": "%"}}}
```

`rocm-smi --showfan --showtemp --json`でも、level 51、20%、1,065 RPMでした。
sysfsのfan1_maxは5,500 RPM。調査中の温度はedge 39〜45°C、junction 41〜47°C、memory 42〜50°C程度でした。

## 変更試行

サンドボックスでは/dev/driが非公開でNoNewPrivs=1のため、許可されたホスト実行で調査しました。
sudoは全て`sudo -A`を使用しました。

`amd-smi set --gpu 0000:0b:00.0 --fan 40% --json`はAMD CLIの対話入力でEOFとなり、設定に到達しませんでした。
続いて作成したFFIから公式APIを呼びました。

```text
before: {'rpm': 1066, 'level': 51, 'level_max': 255, 'level_percent': 20.0}
set 40%: amdsmi_set_gpu_fan_speed: AMDSMI_STATUS_NOT_SUPPORTED: Command not supported. (status=2)
final: {'rpm': 1066, 'level': 51, 'level_max': 255, 'level_percent': 20.0}
```

`gpu_od`も`pwm1_enable`も存在せず、pwm1は読み取り専用です。
fan1_targetはファイルが存在しても、ドライバの手動ファンモード取得経路が非対応なので代替になりません。
公式APIの失敗と前後の測定から、現在の設定では変更できなかったことを確認しました。

## 作成したCLI

`uv run --offline fan_control.py status --json`で以下を確認しました。

* AMD SMI: 1,066 RPM、level 51/255 = 20%
* hwmon: 1,066 / 5,500 RPM = 19.38%
* backend: null、OverDrive無効と必要マスク0xfff7ffffを診断
* `set 40`は制御インターフェース非公開として書き込み前に終了
* Python構文チェックおよび14件のハードウェア非依存テストが成功

## 再起動後の実機検証

ユーザーによる再起動後、動作中のマスク0xfff7ffffと`gpu_od/fan_ctrl`の出現を確認しました。
初期カーブは全5点が0°C・0%、許容範囲は温度25〜100°C、PWM 20〜100%でした。
`fan_zero_rpm_enable`はファイルがあるものの空欄でした。

実装を修正し、初期カーブが全点ゼロなら許容温度内の25、44、63、81、100°Cへ設定点を配置し、
PWMを全点40%にそろえるようにしました。空欄のZero RPM項目には書き込まないようにしました。

実行したコマンド:

```bash
uv run --offline fan_control.py test 40 --gpu 0000:0b:00.0 --settle 8 --seconds 10
```

ホスト上で実行し、スクリプト内部の`sudo -A`で昇格しました。終了コードは0でした。
生出力は[2026-10-23-test40.log](2026-10-23-test40.log)に保存しています。

| 状態 | RPM | hwmon PWM | 備考 |
| --- | ---: | ---: | --- |
| 変更前の自動制御 | 1,066 | 20% | SMI設定割合は0/100 |
| 固定40%、8秒後 | 2,052 | 40% | 全5設定点の読み戻し一致 |
| 自動制御復帰、2秒後 | 2,014 | 減速中 | カーブは全点ゼロへ復帰 |
| 自動制御復帰後、減速完了 | 1,064 | 20% | edge 37°C、junction 37°C、mem 40°C |

変更中に別コマンドから照合しました。

```text
amd-smi metric --gpu 0000:0b:00.0 --fan --temperature --json:
  rpm=2051, speed=0, max=100, usage=0.0%
rocm-smi --showfan --json:
  Fan speed (level)=102, Fan speed (%)=40, Fan RPM=2052
```

AMD SMIのRPMとhwmon/ROCm SMIのRPMは一致しました。
AMD SMIの設定割合は手動40%でも0%のままだったため、CLIにhwmonのPWM割合を独立表示する処理を追加しました。
PWM 40%時の実測RPM比は2,052 / 5,500 = 37.31%で、両者は同じ量ではありません。

自動制御復帰後にカーブ全点が初期のゼロ値へ戻り、PWMとRPMも元の水準に戻ったことを確認しました。
復帰直後はファームウェアによる減速の途中なので、即座に元のRPMにはなりません。
この固定PWM検証時点では、温度カーブのユーザー設定、厳密なRPMフィードバック制御、負荷試験は対象外でした。
その後追加した温度カーブ機能の検証は[2026-10-23-curve.md](2026-10-23-curve.md)に記録しています。

最終実装では19件のハードウェア非依存テストが成功しています。
